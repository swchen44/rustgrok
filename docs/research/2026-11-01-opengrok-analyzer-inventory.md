## 1. 母表、預設值與選擇順序

註冊母表是 [AnalyzerGuru.java L254–325](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/AnalyzerGuru.java#L254-L325)：**54 個 array entries**，依序為 47 個 `new` expressions、6 個 `.DEFAULT_INSTANCE`、1 個 `DEFAULT_ANALYZER_FACTORY`。第一項的實際型別是 `FileAnalyzerFactory`，宣告見 [AnalyzerGuru.java L165–167](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/AnalyzerGuru.java#L165-L167)；該 default 同樣經 `registerAnalyzer` 註冊。以下序號嚴格沿母表，不按語言字母排序。

全部具名 factory 都直接繼承 `FileAnalyzerFactory`。其 constructor 把 null 的 names／prefixes／suffixes／magics 轉成空 list，把 null genre 轉成 `DATA`，content type 則保留 null；matcher null 轉空 list。factory 的 `getAnalyzer()` 用 ThreadLocal 快取，呼叫各列的 `newAnalyzer()`。來源：[FileAnalyzerFactory.java L35–127](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/FileAnalyzerFactory.java#L35-L127)、[AnalyzerFactory.java L72–80](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/AnalyzerFactory.java#L72-L80)。`contentType=null` 表示 factory 未提供 MIME，不應自行填成 `application/octet-stream`；也不是已驗證的 HTTP response Content-Type。`hasAnnotations` 是 factory 宣告值，不等於該檔必有 SCM annotation。

辨識先後順序如下，不能只看 array 的先後便推論結果：

1. `find(in,file)` 先執行 `find(file)`；有 filename factory 就直接返回，不再驗 magic。以程式取出的 basename 最後一個 `.` 為界，先查「點前完整部分」prefix，再查最後 suffix，再查完整 name；查詢值均轉 `Locale.ROOT` 大寫。prefix 不是任意 `startsWith`：例如這裡註冊的 `MAKEFILE` 是對最後一點之前字串作 map lookup。來源：[AnalyzerGuru.java L904–973](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/AnalyzerGuru.java#L904-L973)。
2. filename 未命中才看 stream：初讀最多 8 bytes，實讀少於 4 bytes 立即回 null；然後依序 **precise matcher → magic strings → heuristic matcher**。各組 matcher 都沿註冊順序取第一個非 null。來源：[AnalyzerGuru.java L997–1045](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/AnalyzerGuru.java#L997-L1045)；`Matcher.isPreciseMagic()` 預設 false，見 [FileAnalyzerFactory.java L133–175](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/FileAnalyzerFactory.java#L133-L175)。
3. magic strings 先試開頭兩個 space 分隔 words 的完整 lookup，再一個 word，再 `startsWith`；最後一種按字串長度遞減、等長字典遞增排序，因此具體 shebang 能先於 Shell 的 `#!`。opening 按 BOM 或預設 UTF-8 讀取，略過起始 whitespace，合併 whitespace，並處理 hashbang 後多餘空白；不是只拿最初 8 bytes 作所有字串比較。來源：[AnalyzerGuru.java L195–215](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/AnalyzerGuru.java#L195-L215)、[AnalyzerGuru.java L1049–1115](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/AnalyzerGuru.java#L1049-L1115)、[AnalyzerGuru.java L1128–1192](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/AnalyzerGuru.java#L1128-L1192)。
4. `find` 沒找到可回 null；呼叫較高層 `getAnalyzer(in,file)` 才使用 default `FileAnalyzer`。來源：[AnalyzerGuru.java L557–568](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/AnalyzerGuru.java#L557-L568)。不能把沒有 filename rule 的第 1 列寫成總會匹配的 matcher。

下表 `N/P/S/M` 分別是 filename names／prefixes／suffixes／magic strings；`∅` 是該 factory 實際未註冊該種規則。suffix 保留 source literal（包括大小寫），不替換成自行擴充的副檔名清單。`A` 是 hasAnnotations；`D*` 表示 constructor 以 null genre 取得預設 DATA；`P`／`X`／`I` 分別是 PLAIN／XREFABLE／IMAGE。未列 matcher 的列明確為 `∅`。

## 3. 實際 analyzer、xref 與 helper 路徑

下表 `source` 是 `AbstractSourceCodeAnalyzer → PlainAnalyzer → TextAnalyzer → FileAnalyzer` 的繼承鏈（[AbstractSourceCodeAnalyzer.java L51–69](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/plain/AbstractSourceCodeAnalyzer.java#L51-L69)）；`plain` 是直接繼承 PlainAnalyzer；`text` 是直接繼承 TextAnalyzer；`file` 是直接繼承 FileAnalyzer。表內 Ctags 字串是 analyzer 的 `getCtagsLang()` literal，保留上游大小寫，不是 helper 版本或每檔強制 parser 的執行紀錄。

**Ctags 路徑的判讀：** 所有 `source`／`plain` 列繼承 PlainAnalyzer.analyze：當 document 有 FULLPATH 且注入的 `ctags != null` 才呼叫 `ctags.doCtags(fullPath)`；因此 `getCtagsLang()=null` 不代表「完全不呼叫 Ctags」。`TypeScriptAnalyzer` 沒有 override，繼承 PlainAnalyzer 的 null；VB、HCL、Plain 自身明確返回 null。來源：[PlainAnalyzer.java L78–84](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/plain/PlainAnalyzer.java#L78-L84)、[PlainAnalyzer.java L113–135](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/plain/PlainAnalyzer.java#L113-L135)。Guru 只為非 null 的 language 建 default prefix／suffix langMap（[AnalyzerGuru.java L441–457](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/AnalyzerGuru.java#L441-L457)）。Ctags 實際是外部 subprocess，command 取自配置並加入 langMap／extra options；語言能力與內建 fallback regex 受 helper capabilities 影響，見 [Ctags.java L170–239](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/Ctags.java#L170-L239)、[Ctags.java L264–447](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/Ctags.java#L264-L447)。這不是已凍結的 bundled build，也不是每個 mapping 都已 runtime 驗證。

PlainAnalyzer 本身直接繼承 TextAnalyzer（所以第 54 列記 `text`），但自己定義上述 analyze／Ctags 路徑；它的 default symbol tokenizer 來自 FileAnalyzer constructor，見 [FileAnalyzer.java L97–104](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/FileAnalyzer.java#L97-L104)、[L216–223](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/FileAnalyzer.java#L216-L223)。其他 `text` 列 XML、Mandoc、Troff、Uuencode 自行 override analyze，下面分別記錄；不能因 XML 回傳 `XML` mapping 就假設它也走 PlainAnalyzer 的 defs 流程。Archive、ELF、JavaClass 等自行輸出 xref 的 analyzer 不必有獨立 `*Xref` class；`XREFABLE` 亦不等於 source-code lexer。

## 4. Matcher、壓縮與繼承的細節

### 4.1 六個 matcher 的順序與實際條件

只有第 6、7、9、11、12、54 列提供 matcher；同一註冊序中，precise 組先跑 **JavaClass → Jar → Zip**，heuristic 組後跑 **Mandoc → Troff → Plain**，中間是 magic strings lookup。這是從 §1 的分組流程與 §2 的完整註冊列交叉整理的 source 結論，不是執行結果。

- **JavaClass：** 先要求至少 8 bytes、前四 bytes 為 `CA FE BA BE`；接著實際運算是 `((content[6] & 0xff) << 1) | (content[7] & 0xff)`，接受閉區間 `0x2D..0x35`。上游 description 稱 JDK 1.1～Java SE 9；這裡照錄 `<< 1`，沒有擅改成通常的 `<< 8`，也不外推成所有 class 版本皆會 magic 命中。`.CLASS` filename 分支仍可先選到同 factory。見 [JavaClassAnalyzerFactory.java L43–99](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/executables/JavaClassAnalyzerFactory.java#L43-L99)。
- **Jar／Zip：** `ZipMatcherBase` 的 `isPreciseMagic()` 為 true，先比 `PK 03 04`。Zip 不查 extra field 便返回；Jar 另讀最多 1024 bytes，在 local header 的 filename／extra-field 長度給出的範圍內逐 extra-field 找 16-bit ID `0xCAFE`。Jar 早於 Zip，讓此精確分支先被選。見 [ZipMatcherBase.java L42–90](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/archive/ZipMatcherBase.java#L42-L90)、[JarAnalyzerFactory.java L39–67](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/executables/JarAnalyzerFactory.java#L39-L67)、[ZipAnalyzerFactory.java L38–60](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/archive/ZipAnalyzerFactory.java#L38-L60)。
- **Mandoc／Troff：** wrapper 沒 override `isPreciseMagic`，所以是 heuristic。`DocumentMatcher` 要可 mark/reset；依 BOM 或 UTF-8 解讀，先在最多 300 字元對應 block 內確認 LF，接著逐行最多 100 行找以指定 starter 開頭的行。找到 starter 的檢查先於該行其他檢查；否則內容起始的有限 whitespace 後須遇 `.` 或 `'` sentinel。不是「副檔名 `.1` 一律 man page」，也不應簡化成只看首行。見 [DocumentMatcher.java L38–51](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/document/DocumentMatcher.java#L38-L51)、[L100–175](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/document/DocumentMatcher.java#L100-L175)、[L190–227](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/document/DocumentMatcher.java#L190-L227)。Mandoc 的選擇條件只看 `getMandoc()!=null`，不是已驗證 executable 可用；如此配置時 `.TH` 會先由 Mandoc 辨識，否則 `.TH` 可落到後面的 Troff。見 [MandocAnalyzerFactory.java L37–56](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/document/MandocAnalyzerFactory.java#L37-L56)、[L81–90](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/document/MandocAnalyzerFactory.java#L81-L90)。
- **Plain：** 在最後的 heuristic slot；若 `IOUtils.skipForBOM` 辨識有 BOM 就選它，否則 mark/read/reset 最多 80 bytes，以 UTF-8 decoder 嘗試最多 20 字元；malformed／unmappable error 拒絕，ISO control 且非 whitespace 拒絕，至少一個合格字元可成立。仍受上層「最初實讀至少 4 bytes」限制，因此不能以局部 matcher 程式推論 1-byte 檔必定識別為 Plain。見 [PlainAnalyzerFactory.java L49–96](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/plain/PlainAnalyzerFactory.java#L49-L96)、[L99–155](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/plain/PlainAnalyzerFactory.java#L99-L155)。

### 4.2 壓縮、文件與 tokenizer 的條件分支

第 3／22 列的 factory genre 都以 null 取得 DATA，實際 analyzer 卻可在分析後以內層 genre 改為 XREFABLE／DATA。因此 §2 記的是 **factory metadata**，不將它當作所有輸入分析後的 genre。BZip2 的再分析條件在 source 是 `path.toUpperCase().endsWith(".BZ2") || path.endsWith(".bz")`，不是自行正規化後的完整 `.BZ`／`.bz` 對稱判斷；GZIP 要 PATH 以 case-insensitive `.gz` 結尾才進入該委派分支。BZip2 排除直接再選到 BZip2 自身；GZIP 雖有 `cant recurse` 註解，實際分支仍須按程式及輸入驗證，不能據註解保證所有巢狀壓縮行為。見 [BZip2Analyzer.java L48–69](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/archive/BZip2Analyzer.java#L48-L69)、[L84–126](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/archive/BZip2Analyzer.java#L84-L126)、[GZIPAnalyzer.java L54–73](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/archive/GZIPAnalyzer.java#L54-L73)、[L88–131](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/archive/GZIPAnalyzer.java#L88-L131)。

MandocXref 使用配置的 mandoc binary，啟動參數是 `-c -Kutf-8 -Thtml -Ofragment`，有 OS override 才加 `-I os=...`；未配置或 start／finish 失敗保留 plain fallback。即使 mandoc 成功仍執行 PlainXref 取得 LOC；這不等於 fallback 一定顯示，也不是 Java product 需要外部 troff。見 [MandocRunner.java L78–120](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/document/MandocRunner.java#L78-L120)、[MandocXref.lex L68–125](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/jflex/analysis/document/MandocXref.lex#L68-L125)。Troff 使用自己的 [TroffXref.lex L34–64](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/jflex/analysis/document/TroffXref.lex#L34-L64)。JavaClass 的 BCEL 類別來源由 [imports L35–58](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/executables/JavaClassAnalyzer.java#L35-L58)確認；archive 使用的 Java libraries 不是命令列 helpers。

COBOL 不是 factory matcher 分流：先由 suffix 選定 factory，再由 analyzer 在最多 50 個非 blank lines 中讀 `>>SOURCE FREE`／`>>SOURCE FIXED` 指示；沒有指示時，行首字母、`*>` 或長於 80 字元是 free signal，否則預設 fixed。選對應 hyphen-aware tokenizer 與 fixed/free xref，language mapping 固定回 `CobolFree`。見 [CobolAnalyzer.java L58–162](https://github.com/oracle/opengrok/blob/3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3/opengrok-indexer/src/main/java/org/opengrok/indexer/analysis/cobol/CobolAnalyzer.java#L58-L162)。此規則是 source facts，沒有執行 COBOL fixture；同樣不能把 RDATA／RDS 等 suffix 的名稱外推成所有二進位 R 資料都可正常當 R source 分析。
