# Restricted Lucene-style single-term scoring experiment

The opt-in `--lucene-single-term` path in the Tantivy G1 probe handles a single FULL term with boost 1 on a newly built, non-deleted, single-valued candidate index. It visits all matching postings before ranking; it does not take native Tantivy top-K and rerank it. The formula is adapted from Lucene 9.12.3 BM25Similarity, Apache-2.0, with its upstream header, pinned commit, scoped license and notice in the crate. The independent orchestration is MIT; the FULL analyzer remains CDDL. This does not select a product engine.

For `full=main` across alpha and beta on the public source corpus, the independent original QueryBuilder/Lucene probe reports field N=5, sumTotalTermFreq=1,087, n=5, k1=1.2, b=0.75 and boost=1. Candidate reports the same field statistics. Every corresponding hit's frequency, decoded length, norm byte and 32-bit score are present in the original explanation / candidate JSON; the five score bits and norm bytes match by path. All original and candidate hits remain in their emitted order. The original C tie is alpha then beta while the candidate is beta then alpha; candidate equal-score ties use its own doc address and do **not** reproduce original docIDs. `comparison.json` reports both the score/norm matches and ordered-path mismatch without sorting either response. This original index is independent of the earlier performance index.

The additional synthetic sparse-field case is in `tests/evidence/sparse-single-term-2026-11-01`: its original reader has maxDoc=6 but FULL field N=2 and n=1. Candidate has three input documents including an empty field, reports N=2 and n=1, and matches the observed original score bits for its sole hit. The regression test intentionally failed when N was changed to the total three input documents. The 256-entry Lucene and Tantivy norm **decode** tables compared byte-for-byte equal; that does not prove every norm encoder or analyzer input is equivalent.

This is a finite, restricted diagnostic, not general ranking parity. Deletes and unmerged statistics, multiple fields/values, boosts, phrases, multiple terms, query rewrite, constant scores, Unicode offset semantics, unknown norm encoders, collection cutoffs and original tie identity are not established. Floating-point results are measured for these cases, not guaranteed across platforms. No original docID is read by the Rust scorer; no benchmark of this scorer was performed.
