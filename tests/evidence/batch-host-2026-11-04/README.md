# Fixed-registry batch host correctness

This macOS development host uses the existing owner/peer-checked local Unix socket and one worker to index an explicitly supplied, fixed project registry through the existing atomic durable batch store. The real subprocess tests create two synthetic Git projects with nested Git metadata. With a feature-only pause after the second project is opened for scanning, four simultaneous client processes query the two projects and receive the old generation and expected old paths without `busy`; after release both projects are observed in the new generation. A retained batch snapshot provides one generation per response; separate requests are allowed to straddle a successful commit. Source file-byte maps are compared before and after the tested operation, not source metadata or access times.

Other feature-only subprocess cases exercise cancellation, a second-project unsupported file and unreadable file, stale expected generation, changed registry, panic and post-rename directory-sync failure. Cancellation/failure retain the previous complete batch. Worker panic and indeterminate publication block new queries and indexing until restart; recovery observations are scoped to the injected states, not physical power loss. Tests stop and restart the host and query both projects. New batch requests reject duplicate or unknown fields; the same typed outer request, socket owner/ACL/ancestor validation, handler cap and shutdown machinery remains shared with the original single-project host. Existing single-project suites were run in the same captures. The default binary ignores the feature-only pause mode.

The earlier batch implementation used one nonblocking scratch lock for both reader reconstruction and writer registry validation. A controlled two-reader test first observed `Busy`, then passed after readers were changed to wait for a single reader scratch; a separate controlled test holds reader scratch while the writer completes registry validation and publication. That red output was observed but not saved as a raw stream. One writer and one reader reconstruction can allocate concurrently; the host retains its eight-client cap and one-writer limit. Callers using the library directly must bound their own waiting threads. Frame connect/read/write deadlines remain bounded, but query execution, filesystem operations and waiting for reader scratch have no hard deadline.

[receipt.json](receipt.json) retains host-default, host-hooks and index-default full-suite passes and the initial index-fault attempt marked `BLOCKED_RESERVE`. The latter was stopped when sampled free space fell below the self-imposed 2.5 GiB reserve; a sampled guard can overshoot between checks. After the authorized cleanup recorded in [incremental-cleanup.json](incremental-cleanup.json), only the interrupted index-fault suite was rerun; its separately preserved [receipt](index-fault-rerun.json) and streams report PASS. The original blocked streams and receipt were not rewritten. Default batch-host tests were 3/3, test-hooks batch-host tests 5/5, default batch-index tests 11/11 and fault batch-index tests 17/17; the corresponding streams also include existing CLI and host suites. Actual test binaries and the default/test-hooks executable bytes were verified into the local content-addressed cache before subsequent builds; their hashes and local paths are in the receipts, but binaries are not included in this repository. No performance benchmark or profiling was performed.

This is single-process-at-a-time macOS development functionality, with a private local management socket. It does not implement a batch Web interface, full Q8, source snapshots, complete SCM history, ranked cross-project queries or Linux/Windows acceptance. Every job currently supplies the same complete fixed registry; project addition/removal and subset-job semantics remain unsupported rather than decided. Source and ancestor changes must be coordinated by the caller: observed metadata is not a content hash and a post-validation race remains. Upstream-derived scanner and analysis material retains CDDL notices; new host/batch orchestration and tests are independently authored MIT.
