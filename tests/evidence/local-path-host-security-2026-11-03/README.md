# Local path host security review fixes

This native macOS correctness evidence follows independent review of `053aaa2c183528a15fb42e889df391441a5a6ff6`. The previous [host evidence](../local-path-host-2026-11-03/README.md) and raw streams remain unchanged. It is a bounded local path-only host, not full Q8, cross-platform, release or OpenGrok HTTP/CLI acceptance. No performance measurement was made.

The review reproduced ambiguous JSON dispatch and a control-path bind race. New real Unix-socket tests send duplicated `command`, duplicated `value` including `null`, an escaped duplicate key, unknown fields and invalid UTF-8; they assert protocol errors, no job and a running host. The first duplicate-command test failed on the old parser by actually stopping the host, then passed with typed serde parsing and unknown-field rejection. Frame limits and deadlines are retained.

The old host accepted a private leaf beneath a non-sticky 0777 ancestor. The new test creates that layout and a real macOS extended ACL granting `everyone` write access while mode bits remain 0700; both are rejected before binding. An ordinary owner-only control directory under a trusted sticky ancestor succeeds. The implementation requires each opened control ancestor to be root/effective-UID owned, local APFS with known extended-security/non-opaque capability values, and not group/other writable unless sticky; it rejects every extended ACL and every ACL lookup failure except the locally observed no-ACL `ENOENT`. This deliberately excludes common deny-only home ACLs, other filesystems and opaque authorization; it does not change user ACLs. [receipt.json](receipt.json) records native SDK version and `sys/acl.h`/`sys/unistd.h` hashes, the SDK `ACL_TYPE_EXTENDED` value and the locally observed `/private/tmp` capability values. Unknown configurations fail closed rather than being inferred safe.

A second controlled test paused a real host after validation, then a separate same-UID test process renamed the control directory and substituted a symlink to source. The old pathname bind wrote a socket inside source. The fixed host uses the retained directory fd, performs relative bind through `fchdir` during single-threaded startup, restores cwd before host threads, and uses descriptor-relative identity checking and `unlinkat` for cleanup. In the rerun, no source socket was created, a source sentinel survived shutdown, and the actual owned socket was removed from the retained directory. One-shot clients also connect relative to a retained directory fd before starting application threads. This was a same-UID simulation of the writable-ancestor attack; a real different-UID run was not performed. The ancestor/mode/sticky/ACL controls address the different-UID entry point under the documented local APFS trust model; adversarial same-UID mutation of the retained control directory remains outside the guarantee.

The independent reviewer also identified, by source inspection, a possible caught-panic/state-publication window. A controlled test paused the worker after catch but before fault-state update and reproduced a successful query on the old version. The fix sets an atomic panic latch during unwinding, before catch returns; queries check it before and after snapshot, and new writers check before admission. The same controlled schedule now returns `worker_panic`. This establishes the tested latch boundary, not a zero-time guarantee at the physical instant of panic or behavior under abort-mode termination.

[receipt.json](receipt.json) records commands, native environment, source and raw stream SHA-256, SDK identifiers and observed binary hashes. [Default stdout](default.stdout.txt) is 12/12, [test-hooks stdout](test-hooks.stdout.txt) is 20/20; corresponding stderr streams are preserved. Hash-matched binary bytes are retained only on the development Mac at the `binary_retention.local_path` entries in the receipt and were rehashed after copying. The default was recovered after the run from a matching Cargo deps executable; the test-hooks binary was copied from the target before a later rebuild. These local files are not part of the public repository or a bit-reproducible build claim, and may be absent on other machines. `test-hooks` pause/fault seams must not ship, and default build tests confirm they remain inactive. [dependencies.json](dependencies.json) records Cargo.lock checksums and declared licenses, not a release SBOM or completed notice review. Source hashes in old receipts can be checked using Git history; shallow clones missing the original commits cannot complete those historical checks. Linux/Windows, a real different-UID race, non-APFS behavior and physical power loss remain unverified.
