# Tantivy scorer observation

Seven cases use the exact captured original responses copied byte-for-byte here from `tests/evidence/search-spike-2026-11-01/oracle-inputs` and the public-source scan index SHA-256 recorded in comparison.json. Project selection happens before building the in-memory Tantivy index. No candidate hit or original result was reordered. Candidate raw responses include Tantivy explanations, scores, and document addresses; they do not provide line numbers, snippets, tags, pagination or OpenGrok REST behavior.

The candidate was built offline with `cargo build --locked --offline --release` from `experiments/tantivy-scorer-spike`, using rustc 1.94.0 (4a4ef493e 2026-03-02), cargo 1.94.0 (85eff7c80 2026-01-15), Tantivy 0.27.0 and locked dependencies. The initial probe used `TopDocs` directly and failed to compile because it is not a collector in this version; adding `.order_by_score()` follows the local Tantivy 0.27.0 API. comparison.json records exact binary, lockfile, input, and per-response hashes. The candidate was run with each named field/query/projects in comparison.json. All seven count values matched; four ordered path lists matched. This is not evidence of general rank or API parity, and no performance measurement was performed. The public corpus totals 3,969 source bytes and is not representative of the expected workload.
