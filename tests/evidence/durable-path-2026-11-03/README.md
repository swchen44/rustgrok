# Durable path component correctness evidence

This is a constrained Rustgrok Q8 component test, not full product or OpenGrok compatibility acceptance. The add/remove scenario builds on the pinned upstream `IndexerTest.testIncrementalIndexAddRemoveFile`; its source, hashes and CDDL provenance are recorded in [the earlier path-index evidence](../path-index-2026-11-03/README.md). Crash, storage, cancellation and restart cases are Rustgrok-specific and `tests/durable.rs` is independently authored MIT code.

The captured native macOS test command, UTC time, base commit, compiler, OS, architecture, source/input hashes and raw output hashes are in [receipt.json](receipt.json). The process exited 0 with 26/26 tests in [stdout](durable.stdout.txt); [stderr](durable.stderr.txt) contains cargo output. The receipt binds the run to file bytes, not to a subsequently created commit. The `fault-injection` feature is only for this test; a separate default-feature run passed 19 durable tests and 14 existing generation tests. Analyzer tests, formatting and clippy also passed in the working session. No performance measurement was performed.

The cases include exclusive cross-process lock, old reader during a paused post-rename directory sync, injected post-rename sync error with an indeterminate outcome, invalid pointer and generation records, `_exit` at three publication boundaries with reopen, cancellation, symlink/overlap rejection and simulated ENOSPC before writes. Process exits are not physical power failures; ENOSPC was injected rather than generated by filling a real filesystem. `sync_all`/rename behavior is bounded by the tested macOS filesystem; no `F_FULLFSYNC` or physical power-loss guarantee was established. Linux and Windows have not been validated.

The wrapper takes a caller-supplied manifest and cannot determine whether an otherwise valid manifest omits source files. It does not implement source scanning, xref/history, multi-project atomic publication, ranked search or all of Q8. The store requires exclusive trusted same-user control; checksums are not authentication. See [component documentation](../../../crates/path-index/README.md) for the publication and failure contract.

[dependencies.json](dependencies.json) lists declared registry licenses and lockfile checksums from local Cargo metadata; this is an inventory, not a completed license review, release SBOM, or third-party notice bundle. The component retains the existing analyzer's separate provenance. No dependency or other application is installed or bundled by this evidence.

This historical capture is bound to the source bytes in commit `ab44fe57c1ab3d50bd62a326889570473c51a325`. Later review fixes and their separate evidence do not alter this run. The contract check uses that Git object; a shallow checkout missing it cannot perform the historical source-hash check.
