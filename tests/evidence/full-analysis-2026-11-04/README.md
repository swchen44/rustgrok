# Restricted FULL analyzer evidence, 2026-11-04

Scope: direct `tokenStream` and `normalize` calls over public or synthetic decoded strings, on macOS arm64, using OpenGrok 1.14.20 commit `3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3`, Lucene 9.12.3 and pinned JDK 21. This is correctness evidence, not a performance run, a file-indexing run, or product acceptance. The reader/encoding/tab pipeline, full query parsing, index and ranking are not tested here.

`receipt.json` records 31 runs and their input/output hashes, original analyzer/factory selection, helper source/class, verified upstream source and Java/JAR hashes. `extra/receipt.json` contains four further runs. Captures include the C/Python/JavaScript public source fixtures, ASCII controls, expansion, length boundaries, and normalization. `sigma-matrix-receipt.json` and its raw streams cover 81 finite short uppercase-sigma contexts. Original positions and offsets are UTF-16; UTF-8 input spans are separately computed by Rust. The original stream reports final `END 0`; this slice does not expose that end attribute.

`FullAnalysisOracle.java` is a CDDL diagnostic adapter; OpenGrok sources and notices retain their own CDDL terms. The independent Rust test is MIT, and existing public-source fixture notices apply. `src/full.rs` retains individual upstream provenance and [license](../../../crates/analysis/LICENSE.txt). The original compilation/run commands and source hashes are in the receipts. The Java helper class bytes are retained locally at the hash-named path in `class-retention.json` (not part of the repository); the helper source and pinned dependencies permit recompilation. The original temporary classpath directory is no longer persistent. The capture helper was subsequently extended for `--extra`; it did not rewrite earlier raw captures.

The original token stream can emit a 33000-byte term for 11000 Chinese characters although Lucene's indexed-term byte limit is 32766. Previous [original indexer evidence](../long-token-indexer-2026-11-01/README.md) records per-file failure despite overall exit 0. An additional surrogate-boundary tokenization capture records an isolated UTF-16 surrogate; this restricted API explicitly rejects the unsupported supplementary letter and does not claim the full indexer's failure was caused by that token.

`lucene-bytecode-receipt.json` binds read-only `javap -c` output of the fixed Lucene classes to the archive-verified JDK and Lucene JAR. It is bytecode inspection, not a complete Lucene source audit. No claims are made about Unicode outside the finite supported set.
