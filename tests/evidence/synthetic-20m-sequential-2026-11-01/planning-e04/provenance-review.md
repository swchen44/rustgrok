# e04 planning archive: ignored logs and provenance

The historical ZIP is retained byte-for-byte; its decoded SHA-256 remains `51870a6cb16de16e022b050fce098ce2b60e3013669438a7e9626f334f9b8f87`. The independent [`archive-untracked-audit.json`](archive-untracked-audit.json) identifies 18 entries that were present in that archive and its embedded manifest but absent from the e04 Git tree because `.gitignore` matched `*.log`. Eight are empty Rust candidate logs; ten are Tomcat logs. The ZIP must not be treated as a clean-checkout reproduction of e04, despite its internally consistent hashes.

For the eight live-path runs, the recorded corpus manifest SHA-256 is `88f491850b062ade1fbe157280f78b64b33774820c576dd83337cb11c7ab7c73`; each retained configuration's `sourceRoot` was checked against the public fixture directory. The earliest run does not have a separate `original_source_root_verified` receipt; its retained configuration supplies the narrower evidence. The two project-order captures refer to capture receipt SHA-256 `0558697556728caa51894e8e7199fec11088c2ffe1afd35f15a86e61a82dbc83`; the exact [public capture receipt](original-public-capture-result.json) with that hash records the same corpus manifest. Its five repository paths, origin labels and source hashes were checked against the fixed public fixture manifest. This establishes the recorded input provenance, not complete indexing or search parity.

Privacy review covered all 18 files, not just a token-pattern scan. The eight candidate streams were confirmed empty. Across all ten Tomcat streams, every nonblank line was classified as a Tomcat/OpenGrok/Lucene/Hibernate lifecycle, configuration or shutdown message, an SLF4J/JVM warning, or the documented Java/Chronicle stack trace. Review of normalized message forms, all logged JVM argument names and values, absolute-path contexts, URLs, and address contexts found only the public fixture temporary directories, local runtime/toolchain or default Java paths, the public SLF4J help host, loopback addresses and version strings. No request Cookie/Authorization header, session value, credential-like logged option, or enterprise source text was identified. The streams do disclose the local account name and temporary/runtime paths as environment metadata inside the unchanged archive. This review is bounded to these files and does not prove that any automated pattern search detects every possible secret.

The individual ignored logs are not added to the current Git tree or current planning manifest. Their historical bytes remain accessible inside the unchanged base64 ZIP and retain the hashes in the audit. The current package builder selects explicitly indexed files and rejects unstaged tracked edits; ignored or untracked workspace files are no longer included accidentally. `tests/contract/test_planning_e04_receipt.py` rechecks all 18 historical ZIP entries against the audit and confirms those paths are not in the current manifest. A clean-checkout manifest verification is recorded separately in the implementation report; this historical archive's own manifest is not rewritten.
