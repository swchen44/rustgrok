# Restricted path expression correctness

OpenGrok 1.14.20 commit `3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3`, its release Lucene 9.12.3, JDK and Tomcat were used as a local oracle. The five tiny files are independent synthetic text, not enterprise source; their paths and bytes are in each receipt. The source-provenance file records checked pinned QueryBuilder, CustomQueryParser, PathQueryEscaper, PathTokenizer and upstream test hashes against `upstream/opengrok-source-tree.json`. These original files and upstream adapted content remain CDDL-1.0; Lucene remains Apache-2.0. The new adapter, scripts and Rust parser were independently authored under MIT and do not copy a Lucene parser implementation. The original runtime is a development oracle, not a product dependency.

The first run captures 16 parser expressions plus five unique-filename HTTP coverage queries; `differential/` captures 31 additional parser expressions and the same five coverage queries. Each raw HTTP body, status, query, parser stream, per-run config, indexer streams and artifact/classpath hashes are retained in the respective receipt. Each of the five source paths was returned once by its distinct basename. Query response paths are compared as sets, with result counts checked, not as ranked results. For example, `alpha OR beta AND gamma` parses to SHOULD alpha, MUST beta, MUST gamma; `alpha-beta` is an original single literal, so the new parser rejects that unimplemented syntax. `NOT alpha` produces a pure negative query and zero hits. One deliberately malformed query returned HTTP 400 and is not treated as a successful result.

`oracle-accepted.tsv` contains the derived sets for 41 supported cases from the retained bodies. Contract tests reconstruct it from the receipts and HTTP bodies, and the Rust public API test evaluates every row. These finite cases do not establish full syntax or ranking compatibility; mixed OR/AND at one level, many unary forms, non-ASCII and special syntax remain rejected. The indexer exited successfully and unique filename responses establish these five paths were returned; this is not proof about other inputs. The test corpus and application have single project and path-only scope; Q8, Web and product compatibility remain incomplete.

To repeat independently on the documented local toolchain, choose a new output directory outside the repo and run `python3 tools/capture_path_query_oracle.py --output /tmp/NEW-DIR`, or add `--differential` for the second case set. The current capture helper accepts an explicit fresh output directory; the two retained runs used its earlier default-output form before this safety improvement. The recorded fixture-content metadata was corrected to represent the actual trailing newline, as noted in the receipts. Absolute temporary paths in raw logs/config describe those historical runs and are not current settings. No timing, profiling or performance test was performed.

The post-change native macOS test receipt records path-index integration groups of 21, 14, 4 and 2 passing tests, the default CLI 4/4 and host 15/15, and test-hooks CLI 6/6 and host 23/23. The earlier reviewer startup timeout was not diagnosed by these passes. A separate run using the current helper wrote its original raw capture to `/private/tmp/rustgrok-query-repro-20261103`; its parser bytes and all 21 HTTP status/result sets matched the first retained capture in this session. That extra raw capture is local and is not included in this repository.
