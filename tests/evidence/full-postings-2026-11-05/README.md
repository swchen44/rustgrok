This is a development macOS arm64 correctness slice for issue #6, not complete OpenGrok compatibility, ranking, performance or any of the 80 product acceptance tests. Original OpenGrok 1.14.20 commit `3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3`, Lucene 9.12.3 and archive-verified JDK 21 run independently; the Java process exits before Rust execution. No product JVM dependency, engine choice, host/Web/SCM expansion or source reading snapshot is introduced.

## Contract

`full-create PARENT NAME SOURCE utf8-default-tabs`, `full-index STORE SOURCE EXPECTED PROJECT...`, `full-query STORE SOURCE PROJECT TERM` use a distinct versioned FULL store. Existing path stores/commands remain unchanged; cross-open is rejected, no migration or sidecar publication. Every fixed-registry project is rebuilt successfully before a single `CURRENT` rename publishes paths, source size/hash metadata, term dictionary and inverted doc postings together. Empty registry, subset/changed registry, unrecognized files/paths and unsupported inputs fail closed. Query results are unordered candidates with positions and source SHA-256; no score or OpenGrok ordering claim.

Reader proof follows `TextAnalyzer.getReader` → `IOUtils.createBOMStrippedReader(...UTF_8)` → `ZeroReader` → `PlainAnalyzer.getReader` → conditional `ExpandTabsReader`. ZeroReader guards zero-length read returns and does not transform NUL. Supported configuration is valid UTF-8 with optional leading UTF-8 BOM and no custom project tab setting. Tabs, CRLF and NUL are retained. UTF-16 BOMs, malformed UTF-8, unsupported configuration and analyzer Unicode/context fail explicitly. Unmarked bytes are interpreted only under the explicit UTF-8 contract; no encoding detection is claimed. UTF-16/custom tab/general encoding support remains unimplemented.

Reader UTF-16 offsets exclude a stripped BOM and preserve original lowercase-expansion behavior, including overlaps. File byte spans add the BOM's three bytes and delimit the actual original source bytes. No raw source/reader text is stored or altered; persisted source hash is metadata for the indexed bytes, not a promise that live reading content has the same version. The caller coordinates source changes; repeated metadata and byte-hash checks detect observed changes, not an atomic source snapshot or complete G1 consistency contract.

Ordinary original `CustomQueryParser` single terms use FULL stream analysis: `İ` becomes `i` plus combining dot and `AΣ` becomes `aς`. Multi-term `normalize_full_query_term` is a separate API and is not used here. The CLI rejects grammar, controls, punctuation, Boolean operators, unsupported analysis and anything producing other than one complete identifier-like token. This does not implement full query parsing.

Default hard development bounds: 32 projects, 10,000 documents, 8 MiB/file, 16 MiB source bytes/batch, 200,000 postings, 32 MiB/encoded generation, generation IDs through 32, two live in-memory generations; scanner path/directory bounds also apply. These are explicit admission guards, not a product SLO or accepted resource tradeoff. Immutable on-disk generations are retained; failed prepared records can consume an ID. No garbage collection or unbounded history claim.
