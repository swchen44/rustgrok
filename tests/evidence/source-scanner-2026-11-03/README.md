# Source scanner: bounded correctness evidence

Issue #6; FR-008/009/021, WP-C07/C09, SRC-001/002 and RST-009. This is a macOS-only single-project path component, not full product, search ranking, SCM/history, or Q8 acceptance. No performance measurement was run.

The earlier independent original OpenGrok 1.14.20 run used the public fixture at pinned commit `3ca9d73ebb0ddb5560fbc7631322d29d9fdc2ec3`; its raw [indexer logs and path coverage](../live-path-no-hit-verified-2026-11-01/README.md) show five original path hits, including three alpha paths from three Git repositories with a nested Git. Those paths are compared as an unordered set by the Rust integration test, which builds fresh local `git init` repositories and copies the exact public C/JavaScript fixture bytes. Its Git metadata/history is not identical to the earlier deterministic corpus. The subsequent Python add/remove case is a Rust-specific behavior test, not a fresh original comparison. Original order, history, file contents and all configurations remain unverified. Public fixtures preserve their own [CDDL source and notices](../../fixtures/public-source/README.md); the behavior-derived Rust scanner and its test retain the CDDL header and notices.

[Captured original XML](../live-path-no-hit-verified-2026-11-01/configuration.xml) records `.git` in both ignored file and ignored directory lists. The pinned `RepositoryFactory.initializeIgnoredNames` adds ignored names from each enabled adapter to that global list, and `GitRepository` registers `.git` for both; `IndexDatabase.accept/indexDown` applies `PathAccepter`, readability, symlink and special-file checks. The implementation intentionally errors on unsupported inputs rather than implementing other configured filters or inventing repository ownership. These source facts do not establish behavior for every configuration or filesystem. Exact pinned source hashes are in [receipt.json](receipt.json) and match the already verified [upstream inventory](../../../upstream/opengrok-source-tree.json).

The [receipt](receipt.json) records command, environment, base commit, source/test/input hashes and output hashes. [stdout](scanner.stdout.txt) records 4/4 integration tests with fault injection; [stderr](scanner.stderr.txt) contains cargo output. The feature is test-only. A separate default-feature run passed 2 scanner, 21 durable and 14 generation tests. The fault-enabled durable suite passed 30 and existing generation suite 14. Formatting and clippy passed. The captured tests exercise add/remove/restart, retained old readers, concurrent writer rejection, unsupported inputs and a persistent mutation observed before publication.

Only metadata is compared between traversals; unchanged metadata is not a byte-level content guarantee. A change undone between observations, or after the last check, may go undetected. The caller must coordinate source and ancestor mutations for the whole operation. This restriction, the absent content/xref/history generation and cross-project switch, and the narrow filename/type rules mean full Q8 and general OpenGrok compatibility remain blocked. No physical power-loss, Linux or Windows test is claimed.
