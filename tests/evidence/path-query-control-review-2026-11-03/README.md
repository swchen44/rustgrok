# Control-character query review and correction

The independent review of commit `89f9ae6a21d51d848977852ab5c6705dd3724900` compared the pinned original OpenGrok 1.14.20 parser and HTTP server with the Rust CLI on the same five public synthetic paths. `alpha AND\u000cbeta`, `alpha OR\u000cbeta`, and `alpha NOT\u000cbeta` each returned zero hits in original HTTP, while the old Rust CLI returned one, four and two respectively. Plain-space AND and OR were matching controls. The reviewer ran original capture to completion before Rust CLI, as recorded in the retained reviewer material. Ranking was not compared.

The independent original parser streams, HTTP bodies, configuration, indexer logs, raw Rust outputs, comparison and finding are copied without modification. `reviewer-subset.json` records SHA-256 for each copied file and the local location and hash of the full reviewer receipt; that full receipt is not distributed in this repository. The original HTTP receipt in `original-http/` binds query inputs, tool hashes, status, bodies and fixture. The original synthetic fixture has no enterprise source. Source provenance and CDDL/OpenGrok, Apache/Lucene and independent MIT adapter distinctions remain in [the prior capture](../path-query-2026-11-03/README.md). Earlier evidence is unchanged.

The restricted lexer now recognizes ASCII space only as a separator and rejects all C0 controls and DEL, including form feed, vertical tab, tab, CR and LF. This is a deliberate unsupported-input boundary; it does not claim OpenGrok rejects or treats these characters the same way. An API regression first failed on the actual `alpha AND\u000cbeta` input and passed after the fix; the red run was observed but its raw output was not retained. The API covers every C0 byte and DEL after each of AND, OR and NOT. The subprocess tests check three form-feed variants for both direct and host commands, followed by normal successful queries; host test-hooks also check rejection while a new generation is paused, with the old generation still readable. The existing result-limit check remains exercised. No performance test was performed.

`rust-test-receipt.json` records serial native macOS tests, command inputs and raw output hashes. Default and feature-hook product binaries from the actual test runs are retained locally at their content-addressed cache paths and verified before the next build; binary bytes are not distributed in this repository. Native macOS correctness is not Linux or Windows acceptance, complete Q8 or full OpenGrok grammar/ranking parity.
