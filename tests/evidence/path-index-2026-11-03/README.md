# Path index component evidence

This is a single-process, single-project in-memory postings component, not a full Rustgrok indexer or a crash-safe Q8 implementation. [provenance.json](provenance.json) records the pinned 1.14.20 commit, original `IndexDatabase` and `IndexerTest` source hashes, and SHA-256 of the existing original `main`, `mai`, `ain` diagnostic streams. The source hashes match the previously verified upstream tree inventory. The original `IndexerTest` supplies the add/remove test scenario; the Rust test has the original CDDL header and copyright.

The raw diagnostic's original query selected alpha and beta. The component integration test takes its alpha-path projection and compares only unordered candidate sets for the three one-term path queries. This does not compare score, ordering, HTTP, other queries, source selection or complete OpenGrok behavior. Existing raw outputs are unchanged and their limits are described in [the original diagnostic](../path-ranking-diagnostic-2026-11-01/README.md).

The captured local test run in `test.stdout` / `test.stderr` uses only an independently authored temporary synthetic source fixture and logical path manifests. It exercises add/remove, explicit empty generation, completeness-count validation, original candidate projections, unsupported queries, Unicode errors, invalid/corrupt source iterator data, I/O failure, resource and retained-generation limits, cooperative cancellation, cancellation/publication race, concurrent/stale writers, iterator panic and continued old-reader access. It does not prove filesystem scanning, actual persistence/crash recovery, full Q8, Q9 live reading or product parity. Full product test IDs remain planned. No performance measurement was made.
