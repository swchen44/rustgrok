# Explicit source batch and direct CLI correctness

This native macOS development slice extends the separately marked fixed-registry batch store from [batch publication evidence](../batch-publication-2026-11-03/README.md). `batch-create`, `batch-index`, `batch-query` and `batch-query-expression` operate on explicitly named `sourceRoot/<project>` directories. The first successful index fixes the registry; later jobs must supply the same complete set, in any order. Unlisted root entries are not auto-discovered. The shared scanner's restricted filtering and descriptor rules remain in [scanner evidence](../source-scanner-2026-11-03/README.md); the scanner-derived code retains CDDL provenance and notices. New batch/CLI orchestration and tests are independently authored MIT.

The real subprocess e2e creates two synthetic projects, real Git metadata and nested Git, then indexes and queries both from separate CLI processes. A second-project unsupported file, unreadable file and symlink each reject the replacement; the raw `CURRENT` bytes and both project results stay at the old batch. Removing the blockers and indexing with the same registry in reverse order publishes one new generation for both. Source file byte maps before and after each operation match; this does not assert metadata or access times are unchanged. Subset, duplicate, unknown, traversal names and mixing single/batch stores fail explicitly. A separate API test covers aggregate limits, project symlink and duplicate names.

Feature-only tests pause after opening the second project and send real SIGINT; cancellation returns exit 130, the batch pointer is unchanged, and both project queries after process exit read the old generation. A separate process query while the batch index owns its lock returns `busy`. Another test pauses before publication, modifies the second project's file and observes `source_changed` with the old batch preserved. The default binary ignores both test-pause environment settings. The pauses are controlled test hooks, not product scheduling or a performance measurement.

All named directories are scanned before publication and checked again immediately before the existing single-pointer commit. Per-project and aggregate path and directory-entry budgets are bounded; aggregate checks occur after each project and can overshoot by one bounded per-project scan before rejection. The source root and store are disjoint; source contents are not written. The caller must coordinate source and ancestor mutation throughout scanning. Metadata is not a content hash, a post-check race remains, and same-UID adversarial pathname replacement is not excluded. A blocked filesystem call is not forcibly interrupted. These tests do not establish complete Q8, live/scm reading consistency, ranked cross-project search, Web, a batch host or Linux/Windows support.

[receipt.json](receipt.json) records four sequential offline correctness suites, source and stream hashes, a 2.5 GiB sampled free-space guard and the actual local cache paths/hashes of each test executable and default/hook CLI binary, retained before the next build. The guard is self-imposed and was lowered from the previous 3.5 GiB reserve for these small incremental builds; it is not a system quota. Batch CLI tests passed 4/4 default and 5/5 test-hooks; batch index tests passed 11/11 default and 15/15 fault-feature. Existing path-index, CLI and host suites also passed in the corresponding streams. These limited native results do not count as the 80 product acceptance cases. No benchmark or profiling was performed.

An earlier successful four-suite run is preserved in `pre-lint/`. Its source receipt differs from the final test input only by the later addition of a scoped Clippy annotation to `scanner.rs`; the evidence contract reconstructs the earlier bytes and checks that hash. The final four suites were run again with the final source bytes; their streams and binaries are the primary receipt above.
