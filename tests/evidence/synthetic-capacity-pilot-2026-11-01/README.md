# Synthetic indexing capacity pilot, macOS arm64

This pilot used independently generated, repeated comment text, not company source. It had 10 projects, 4 C/Python/JavaScript files each, 65,536 bytes per file, and 2,621,440 source bytes total. It has no SCM repositories or history and is not representative of actual source, the requested approximately 500 MB workload, production search, or full product parity. The checked-in manifest and generator define every input byte; the saved candidate JSON contains only this synthetic data. The 16 MiB hard input cap on this pilot runner prevents starting a 500 MB index run before a separate resource assessment.

Both indexers exited zero. The saved original stdout/stderr have no detected `ERROR addFile()` or nonzero parallel-index failure message and contain the expected completion markers. The original log reports Perforce `p4` unavailable and Java native-access warnings; this corpus has no repositories, so it does not test SCM behavior. Four raw HTTP path responses from an isolated original index copy contain exactly the 40 expected synthetic paths. `coverage.json` also records that the original index tree hash was unchanged while querying. The Rust JSON index's 40 paths and source contents match independently generated bytes; its saved SHA-256 is in `report.json`. The original path check shows path presence, not that every source token is searchable or that other query semantics match. No search latency comparison was made.

The second pilot recorded original index/data size 616,774 bytes and candidate JSON index size 2,668,891 bytes. These indexes implement different features, and their sizes are not an equal-function comparison. `/usr/bin/time -l` records original indexing 1.59 s real, 3.67 s user and 0.29 s system CPU, with a maximum resident set of 210,599,936 bytes; the candidate records 0.15 s real, 0.09 s user and 0.04 s system, with 7,733,248 bytes maximum resident set. The time tool reports zero block-input/output operations for both; those counters do not establish zero byte I/O, and process accounting may not represent a simultaneous peak of all descendants. Raw logs, process-group snapshots, `time` output and the measured candidate index are retained. Original index bytes remain in the local pilot directory only; they are not included in this repository evidence, so the exact original generation cannot be reconstructed from the repository alone.

Disk monitoring used a 6 GiB free-space reserve, with approximately 0.25-second intervals plus up to 0.25 seconds for process sampling during indexing; scheduling and filesystem updates can delay detection. The original process was stopped if a sampled free-space value fell below the reserve. The separate HTTP-check monitor sampled every 0.25 seconds and stopped its own Tomcat process upon a breach. Across recorded samples, free space started at 7,555,006,464 bytes and reached a low of 7,484,071,936 bytes, a 70,934,528-byte observed difference that includes other machine activity. These snapshots do not bound peak writes or prove the reserve was maintained between samples; no strict maximum disk consumption has been established. They are insufficient to extrapolate safely to a 500 MB index run on a disk with roughly 7 GiB free.

An earlier attempted HTTP check returned all 40 paths but directly opened its original index, whose tree hash changed. `earlier-blocked/` retains that run's raw responses, the `BLOCKED` receipt, and the corresponding raw indexer stdout/stderr recovered from its own temporary output and checked against that run's recorded hashes. The later successful check copied the original index first, set the copied `dataRoot`, and set `allowMostPopular=false` for the user-deferred suggestion feature; this differs from the upstream default. No source corpus or other pre-existing user data was deleted.

Reproduce on a host with the verified original toolchains and adequate free space, using new external output paths:

```sh
python3 tools/build_synthetic_corpus.py create --output CORPUS --projects 10 --files-per-project 4 --bytes-per-file 65536
python3 tools/run_synthetic_index_probe.py --corpus CORPUS --output INDEX_PROBE
python3 tools/verify_synthetic_paths.py --corpus CORPUS --probe INDEX_PROBE --output PATH_OBSERVATION
```

`tests/contract/test_synthetic_evidence.py` rechecks the manifest, retained candidate content/hash, all four original response path sets and unchanged-original index receipt. The reserve check is a sampled protection, not an operating-system quota.
