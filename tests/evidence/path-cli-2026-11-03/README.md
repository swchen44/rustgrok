# Restricted path CLI subprocess correctness

This is a native macOS development CLI test, not an installed-product release, full Q8, original OpenGrok CLI/HTTP, ranked search, SCM or browser e2e acceptance. No performance measurement was made. GitHub #6 tracks this path slice; #5 tracks its reference corpus. The source add/remove scenario is based on the pinned OpenGrok 1.14.20 `IndexerTest.testIncrementalIndexAddRemoveFile` (component-level upstream integration, not upstream browser or CLI e2e). Its commit, source hashes and license provenance are in [upstream evidence](../upstream-integration-2026-11-03/source-provenance.json). Tests use real temporary `git init` repositories, one nested, and copy the CDDL public C/JavaScript source fixtures with their own [license and provenance](../../fixtures/public-source/README.md); no enterprise data.

[receipt.json](receipt.json) records each actual command, environment, base commit, input and raw stream SHA-256, and the observed compiled binary hash immediately after each run. [Default stdout](default.stdout.txt) shows 3/3 tests, with [stderr](default.stderr.txt); [test-hooks stdout](test-hooks.stdout.txt) shows 5/5, with [stderr](test-hooks.stderr.txt). The two observed binary hashes differ. If these source inputs change later, the evidence contract checks the commit that introduced the receipt; a shallow clone lacking that history cannot perform the historical-source check. Those binaries are not retained as evidence and their hashes are observations, not independently reproducible-build attestations. The default test confirms the test-pause environment variable has no effect without the feature.

The tests execute the actual CLI as separate processes and assert exact JSON/exit categories for creation, indexing, unranked queries, add/remove, reopening in a new process, bad generation/query, unsupported file, symlink and a corrupt CURRENT. The corrupt store is rejected; the test restores its saved pointer before demonstrating old-generation recovery. It compares source fixture files including Git metadata before and after commands. With `test-hooks` only, a deterministic pause inside a real indexing process allows a second query process to observe `busy`, sends a real SIGINT and verifies `cancelled`/exit 130 and old-generation recovery, and detects a source change before publication. The pause and stderr markers are test-only and must never ship; SIGINT timing on a normal default binary was not separately synchronized or observed. Cancellation is cooperative and late signals can lose to publication.

The store uses an exclusive cross-process lock. A separate CLI query cannot read while the indexing process holds it, so these tests do **not** satisfy Q8 concurrent read availability. Source changes must be externally coordinated across scanning and publication; metadata checks do not prove byte equality and are not atomic with publication. The interface supports a restricted subset and errors on unsupported source names/types; it has no source-content index or OpenGrok result ordering. Only native macOS was tested. Linux/Windows and real power-loss recovery remain unvalidated.

[dependencies.json](dependencies.json) records 21 Cargo.lock registry packages and their declared license metadata; this is not a completed license review, distribution notices bundle or release SBOM. The app's independently authored main file is MIT; upstream-derived test retains CDDL and notices. The analyzer and durable scanner have separate license scopes. See [CLI contract](../../../apps/grok-host/README.md) for exact commands, error labels, limits, and the D19 packaging boundary.
