# Tantivy scoring experiment

This independent, MIT-licensed G1 probe uses Tantivy **0.27.0** (MIT) and serde_json 1.0.140 pinned in Cargo.toml; exact registry dependencies and checksums are in Cargo.lock. This is an evaluation candidate, not a product engine selection or a port of OpenGrok. Each invocation creates an in-memory index for the selected projects; it does not reproduce the original analyzer, query semantics, ranking scope or complete HTTP response.

Build with `cargo build --locked --offline --release` when all locked dependencies are cached. Its input is the JSON output of the search-spike index command; invoke with `--documents FILE --field full|path|def|symbol --query TERM` and repeat `--project NAME` as necessary. The project-scoping and scoring test runs via `python3 -m unittest discover -s experiments/tantivy-scorer-spike/tests -v`.

The seven raw captures and comparison are in `tests/evidence/tantivy-scorer-2026-11-01`. Seven result counts and four ordered path lists matched a single set of original captures. The candidate supplies no original line numbers, snippets, tags, paging or HTTP response. This is neither search parity nor a performance comparison. The original rank also changed between some repeated captures. Full dependency licensing review and release SBOM remain future work.

The FULL field uses a CDDL-scoped experimental adapter of the fixed OpenGrok plain FULL lexer and JFlexTokenizer, while other fields retain their earlier candidate analyzers. `LICENSE.txt` and `OPENGROK-NOTICE.txt` preserve upstream conditions; independently authored `src/main.rs` and `examples/full_token_probe.rs` remain under the scoped MIT notice. The adapter uses regex 1.13.1 (MIT OR Apache-2.0; exact dependency checksums in Cargo.lock). The finite token/position comparisons, Unicode offset mismatch, long-term limitations, and before/after corpus scoring are in `tests/evidence/full-token-diagnostic-2026-11-01`. This is not full analyzer or ranking compatibility.

The scorer rejects a token whose 32,766 UTF-16-unit cutoff would split a surrogate pair rather than silently emitting a different term; original casefold offset behavior is also not yet represented.
The scorer also rejects an adapted FULL term exceeding Lucene's 32,766-byte term limit. This prevents silent acceptance of a known differing case; it does not reproduce original per-file failures or overall exit behavior.

An optional `--lucene-single-term` mode calculates the fixed Lucene BM25 float operation order over every candidate posting for a single FULL term, with field-specific N and candidate norms. Its derived formula is scoped Apache-2.0 in `src/lucene_bm25.rs` (license/notice preserved); the FULL tokenizer remains CDDL and independently authored orchestration remains scoped MIT. The candidate uses its own doc addresses for ties. See `tests/evidence/lucene-single-term-2026-11-01` and `tests/evidence/sparse-single-term-2026-11-01`; exact scores for those finite cases do not imply general query, norm, score or ranking parity. Do not use native top-K as a prefilter for this mode.
